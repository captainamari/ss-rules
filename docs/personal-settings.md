# 🎛 保留个人设置与更新规则

日常在服务组选择地区策略或 DIRECT 即可；各地区组负责节点筛选和自动测速。若需要长期保存“券商固定香港01、邮件固定日本01”等个人设置，可使用 Shadowrocket 的本地扩展配置。

公共配置负责规则与默认组定义；本地配置负责自己的例外和组选择。这里的「香港01」「日本01」只是示例，必须使用手机上真实存在的节点名称。

## 建立本地配置

1. 在「配置」页导入并使用公共 `Shadowrocket.conf`，确认远程规则集加载成功。
2. 点击公共配置，选择「扩展配置」，将新文件命名为 `My-Routing.conf`。
3. 进入 `My-Routing.conf` 的「ⓘ / 编辑配置 → 通用 → 包含配置」，确认它包含的是本机的公共 `Shadowrocket.conf`。包含的是这个可更新的配置文件，不是某个固定版本的规则集 URL。
4. 只在本地扩展文件中保存个人设置。公共文件保留原来的更新地址；本地扩展文件不要设置指向公共文件的远程更新地址。
5. 在「配置」页选择「使用配置 / 编译配置」，将 `My-Routing.conf` 设为当前使用的配置。

完整备用版也可作为被包含文件，但应包含和更新 `Shadowrocket-full.conf`；不同时包含两版。

## 保存需要固定的组

本地扩展配置优先于被包含的公共配置。需要覆盖某个组时，保留相同组名，在本地扩展中保存该组的定义和选择，不要只依赖切换页临时点选是否被某个客户端版本记住。

可在 `My-Routing.conf` 的「代理分组」中添加/编辑对应组。若界面只展示继承项、不能明确区分本地项，可按以下方式操作：

1. 在公共配置的「预览配置 / 编辑纯文本」中找到需要调整的那一行，例如 `📈 券商服务 = select,...`，复制完整定义。
2. 将它放进 `My-Routing.conf` 的 `[Proxy Group]` 段。不要复制公共文件的 `[Rule]` 段或 `update-url`。
3. 要固定节点时，在本地这组的策略候选中加入节点的准确名称，并将 `policy-select-name` 设为该名称。节点可通过策略输入框旁的 `•••` 从客户端现有节点中选择。
4. 保存后使用/编译 `My-Routing.conf`，检查实际连接记录。

例如，手机确实有名为「香港01」的节点时，本地组可以写成：

```ini
[Proxy Group]
📈 券商服务 = select,🚀 默认出口,香港01,policy-select-name=香港01
```

这只覆盖券商组；默认出口、邮件等其他组仍继承公共配置。此示例省略其他候选，只保留默认出口和该节点。需要保留全部地区、直连等策略选项时，应使用复制来的完整组定义再修改选择。服务组使用明确的策略成员，不添加 `policy-regex-filter`；筛选节点和测速仍由独立地区组负责。

选择已有地区组的例子：

```ini
[Proxy Group]
📮 邮件服务 = select,🚀 默认出口,🇯🇵 日本自动,policy-select-name=🇯🇵 日本自动
```

这里固定的是“日本自动”这个选择，并不是固定某个日本节点。要固定节点，请像券商示例一样选具体名称。

国内等直连组可直接选择 `DIRECT`，不需要加入任何节点。

多个组写在同一个 `[Proxy Group]` 段中，不要重复段标题。节点删除或改名、公共组改名时，需要相应调整本地引用；固定节点也不保证服务提供者永远使用相同出口 IP。

## 更新规则而不替换个人文件

为了让更新对象清楚，使用本地扩展时先关闭「设置 → 配置 → 自动后台更新」，按以下顺序手动更新。节点订阅的自动更新是另一项设置。

1. **更新公共文件**：在「配置」页选中 `Shadowrocket.conf`，执行「更新配置」。保留它原有的更新地址。
2. **重新使用个人文件**：选择 `My-Routing.conf`，执行「使用配置 / 编译配置」，加载刚更新的公共规则及对应版本的远程名单。
3. **确认结果**：当前配置应是 `My-Routing.conf`；本地保存的组选择仍在，规则集 URL 应来自更新后的公共配置。

不要用公共远程地址更新 `My-Routing.conf`，否则会替换个人文件。也不要删掉公共文件的 `update-url` 后只重复下载旧规则集：本仓库的规则集地址不可变，新版本通过更新主配置获得。

本地覆盖的完整组定义不会自动吸收公共文件对同名组的成员调整；需要新选项时，重新参考公共组定义并保留自己的选择。

## 在手机上确认设置生效

以下操作用于确认当前客户端的包含、编译和选择行为：

- 查看 `My-Routing.conf` 的包含配置，确认仍指向本机公共文件。
- 保存一项容易识别的本地选择，按上述顺序更新公共文件、重新使用个人文件，再查看该选择。
- 访问 `www.interactivebrokers.com`、`mail.google.com` 等实际服务，查看「数据 → 代理」中的策略和节点。
- 公共配置发布新名单后，检查个人配置编译使用的规则集 URL 是否跟随公共文件变化；没有名单变化时，地址保持不变是正常现象。

如果所装版本没有「扩展配置」或未按预期覆盖同名组，先更新客户端并核对包含关系。仍无法确认时，使用公共配置，并在每次更新后重新选择出口。仓库文件的生成校验不能代替手机上对包含关系和实际节点的确认。
